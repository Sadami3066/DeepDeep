# 设计取舍

这些是**有意为之**的决定，不是缺陷。改代码前按这里判断；要推翻先改本文件并写清迁移代价。

1. **签名**：release 也用 debug 证书。换正式 keystore 会让现装设备无法覆盖安装，`allowBackup=false` 下卸载即丢全部会话与凭据；只在「愿意让所有人重装」的发版点换。
2. **不做二次审批，只分权限档**：个人设备、单人使用，风险自担；系统级能力只有「权限」页三档（普通/无线调试 ADB/Root），ADB 授权走系统无线调试配对，Root 授权交给系统 root 管理器，App 不另做审批流。
3. **单 Activity + 自研 `AnimatedScreenHost` 导航**，不引入 Navigation-Compose；跨层级转场与页面状态保存已按此实现。
4. **`:app` 不拆 `:feature:*`/`:core:*`**：`:runtime-api` 是唯一纯 JVM 契约层；`:app` 只依赖 `:runtime/:shell/:design`，模块边界由 Gradle 任务强制。
5. **本地分发**：不上架；Maven Central 与仓库公开都推迟，等真有外部使用者再说。
6. **会话以 pi JSONL 为唯一权威**：置顶/归档/改名/草稿都是本地元数据，不回写会话正文。
7. **创意工坊页面与 Agent 分层**：WebView 保留独立 origin 与 document-start bridge；页面不能直接调用任意 App 内部函数。页面发起的 Agent 不设目录隔离或权限白名单，复用当前文件、shell、插件与 MCP 配置；调用方可主动缩小工具和技能集合。运行仍是一次性的，不接入目标续跑、定时提醒或聊天交付卡；页面关闭取消，结束时等待本次并行命令收尾，只清理临时会话元数据，保留工作文件；MCP 凭据使用共享存储，刷新结果不会随临时会话删除。
8. **Root 是可选增强层**：默认普通档；选中特权档且 root 可用时注册 `root_shell`（与无线调试是否可用无关）；授权交给系统 root 管理器，App 不做二次审批；前台、后台、定时、目标续跑等任何轮次都可执行。
9. **不做无实测的性能优化**：声称变快必须给 `gfxinfo` 前后数字。
10. **持久化纪律**：原子写（tmp + rename）、坏文件先备份 `.corrupt` 再重建、带 `schemaVersion`。
11. **许可边界**：自有代码 Apache-2.0；PRoot（GPL-2.0-or-later）、Alpine 包、字体/图标、pi2kotlin SDK（MIT）各自许可；不对外说「整个 APK 是 Apache-2.0」。
12. **会话状态只有一个所有者**：`SessionCommandPlane` 用每会话锁与单调 epoch 管理 busy/stop/retry；只有当前 run 能清除 busy，迟到事件按 runId 隔离。
13. **状态与事件分工**：运行状态以 `activeRuns` 为准；事件保持多订阅者广播，UI 从运行快照与历史对账，结构事件不得被流式 delta 挤出顺序。
14. **能力重配置走安全点**：插件能力变化经 `host.reconfigure()`；忙碌会话在本轮结束的安全点应用，不提前关闭正在使用的会话。
15. **会话实时状态是运行时事件的纯投影**：主聊天页、系统助手浮层等任何 surface 都用同一个 `reduce` 与 `SessionProjection` 从 `runtime.events` 还原当前会话；`RunStarted` 对用户轮次携带原文 prompt，界面不得假设「这一轮由自己发起」。界面外壳只保留输入、滚动、可见性等本地状态；消息/过程/工具渲染共用同一套组件。
16. **shell 输出契约**：Alpine Linux 与 Android 系统 shell 保留各自运行环境，共享工作文件使用相同真实绝对路径。所有 shell 工具报告真实退出码、超时、取消和上游截断；普通 Linux 命令返回真正的末尾输出，超出 2000 行或 50 KiB 时提供完整日志绝对路径。上游已截断的 ADB/Root 输出不得伪称完整日志。
17. **浮起面允许着色投影与克制的光效**：输入卡与助手浮层是浮起面，共用 12dp 着色投影（暗色补 1dp 发丝描边）；浮层输入卡可叠加蓝色系深海光晕、半透明底与渐变描边，光效随当前轮次状态变化但只做视觉层，不另建运行订阅。回答首字的流光沿四边自下而上，整圈只保留低强度底光。这是用户明确要求的氛围效果，不要按旧纪律删掉；其余平面内容仍保持无阴影/渐变。
18. **助手浮层是入口，不是第二个聊天页**：唤起时底部滑入输入卡（默认打字；麦克风短按切换、按住说话松手结束；工作区入口在面板标题右侧，点开后先选工作区、再选会话；两级紧凑浮层卡，不撑高面板；模型与思考档同在一个模型 sheet）。发送后顶部滑下会话面板，高度按各消息实测高度实时跟随内容：发送后先长到消息高度，生成中随字符逐行下探，超过半屏后才固定并跟底，空闲时收敛到内容高度（短会话不会先撑满半屏）；键盘打开时面板顶部不动、不隐藏，底部与输入卡之间保留固定间隔并做高度动画（高度动画只在 layout 阶段读动画状态，避免逐帧重组），输入卡单独抬到键盘上方；右上角全屏按钮进 App，不做下拉进 App 手势；点空白/返回关闭浮层。消息、过程、交付与提问复用主界面同一套组件。
19. **轮次生命周期归进程，不归界面**：浮层用应用级 scope 驱动轮次，并作为入口启动前台服务；关闭浮层、从浮层跳进 App 只销毁界面，不取消正在跑的轮次。任何界面切换都不得中断轮次，只有用户主动停止才终止。
20. **发送/插话/排队是运行时语义**：会话空闲时发送即起新轮；忙碌时发送=插话（steer）、长按=排队（follow-up），由运行时统一处理，不与某个界面绑定；队列状态属于共享会话投影，主界面与浮层消费同一份数据。
21. **输入框回车换行，只按按钮发送**：主界面与浮层一致，避免回车误发，多行输入保留换行。
22. **过程行行首转圈 + 本地化耗时取代「思考中」提示**：不再在输入框上方显示思考状态；运行中在过程行最前显示转圈与实时秒数，结束后显示总耗时。
23. **光晕取色**：深色取星空与深海的深蓝，浅色取天空、海浪与浪花的天蓝/海蓝。
24. **光效技术取舍**：优先 Compose 绘制管线；不引入 GLSL、预渲染资源或第三方动画库，除非先证明 UI 线程不是瓶颈；RuntimeShader 只作为 API 33+ 的后续原型。
25. **浮层入场等首帧就绪再起步**：唤起时立即压暗背景并起光效，但输入卡与面板的滑动要等会话加载、面板完成首帧布局后才开始；面板内容列表从底部附近起步，避免先组合顶部再跳到底部。这样入场期间的组合/测量尖峰落在静止背景上，卡片运动本身保持高刷流畅；冷启动的剩余卡顿属于进程/首帧成本，不等于动画卡顿。
26. **语音入口只有一个形态**：旧语音 sheet 及其状态机已删除；主界面输入卡与浮层麦克风统一为「短按切换、按住说话、松手结束」，识别结果回填输入框（设置允许且输入为空时直接发送）。任何入口收到 `ACTION_ASSIST` 都转到系统助手浮层，包括旧版本遗留在系统里、仍指向 `MainActivity` 的助手组件；不再保留第二套语音界面。

27. **权限分三档，后端可用性优先于档位**：普通档只有 PRoot Alpine 里的 `bash`（主动不使用特权）；选中无线调试（ADB）/Root 后按实际可用后端注册工具：ADB 守护可用 → `adb_shell`（App 内嵌 ShellDaemon，uid 2000），Root 可用 → `root_shell`（`su`）；只按 `effective` 注册一个 shell 工具，两者都可用时不再同时暴露，避免模型选错。`effective` 表示默认/显示档位：选中后端可用就用它，否则回落另一可用后端；选普通档仍不启用特权。ADB 档不可用回落 Root、Root 档不可用回落 ADB；存量 `SHIZUKU` 持久值解析为 ADB。启动时仅 `selected != NORMAL` 才探测 root；选择特权档、权限页刷新、手动检测仍探测；root 为 `Denied`/`Unsupported` 时不自动反复探测，UI 提供手动重新检测。`selected`/`effective`/可用后端变化都走 `host.reconfigure()`。虚拟屏幕可用 = 选了特权档且至少一个后端可用，启动时选中后端优先、另一可用随后。
28. **无线调试不再依赖 Shizuku**：项目默认不加第三方依赖；本轮为自建 ADB 配对与守护破例引入 `com.github.MuntashirAkon:libadb-android:3.1.1`（JitPack，Apache-2.0/BSD-3 双许可）、`org.lsposed.hiddenapibypass:hiddenapibypass:6.1`（配对时经隐藏 Conscrypt 取 TLS exporter）、`org.bouncycastle:bcpkix-jdk15to18:1.86`（自签 ADB 证书）、`com.squareup.okhttp3:okhttp:5.4.0`（本地 HTTP 客户端）。不再有 Shizuku 依赖/provider/代码。首次配对通过系统无线调试配对码 + 通知 RemoteInput；配对成功后 App 自己连接一次 ADB TLS、拉起 `ShellDaemon`（uid 2000）后断开，之后全部走 `127.0.0.1:18242` + token。密钥/证书/token 存 App 私有目录，跨升级保留；配对/守护的完整流程见 32。实测环境：Android 16 无 root 测试机通过无线调试配对、冷启动与虚拟屏；Root 回落由单测覆盖（有 root 手机未连机复测）。

29. **悬浮窗是第三层入口**：小鲸鱼气泡用 `TYPE_APPLICATION_OVERLAY` + `SYSTEM_ALERT_WINDOW`，开启后在 App、助手浮层与其他应用上一律显示；点击气泡打开运行面板、再点不做任何事，只有面板右上角 X 收起（虚拟屏小预览打开时点击气泡不动作，避免面板替换预览）；面板跟随气泡一起拖动，拖动自由摆放、不吸附边缘，位置持久化；长按在气泡旁弹出虚拟屏小预览：只看画面，只有再次长按能收起，拖动气泡、点预览外、点气泡都不影响预览；长按时气泡圆周出现蓝色渐变进度环，开启预览顺时针填充、关闭预览逆时针褪色，早于阈值松手则淡出；虚拟屏未运行时不显示画面，只给一块深色短提示 chip，不回退到助手浮层。弹出物（事件卡、运行面板、虚拟屏小预览）按气泡所在半屏选上下：气泡在下半屏弹出物在上、贴圆的顶部，气泡在上半屏弹出物在下、贴圆的底部，近侧内边距收紧到 2dp 让弹出物贴住圆边。提问/完成用气泡旁的事件卡（优先级 提问 > 完成，只在 App/助手浮层不在前台时出现，避免与页内提问重复）：卡片持久显示，点卡片外不再消失；提问卡只在回答后消失，完成卡点卡片打开会话并移除该条、右上角小 X 只标记已读（不删面板「已完成」条目、关闭后下一条接着显示）；多个会话同时有待处理时按单卡队列逐条展示：提问按先到先处理在前、完成按新到在前，header 标签后显示「· N 条」剩余总数（N>1 时），处理一条后下一条顶上来；气泡内只内联单选提问，文本/多选跳助手浮层。事件卡与面板复用运行状态单一来源（`RunActivityTracker` + `QuestionCenter.pending` + `RunFinished/RunFailed` 与 `present` 工具结果），不另建运行订阅。「已完成」不区分是否有交付：所有已结束会话都列出，有交付用交付卡、无交付用回复文本/状态卡；点击条目或气泡卡打开对应会话并立即移除该条；角标 = 待回答 + 未查看完成数；同一会话重新运行时该条隐藏且不计入角标。入口链路：点击面板条目或事件卡 → 助手浮层 → App（长按不再唤起浮层，悬浮窗没有无 session 的浮层入口）。虚拟屏小预览只在长按时按需订阅 ≤5fps 帧，关闭即停订阅，稳定状态不携带帧；不再有面板内预览区与全屏查看器页面。浮窗几何按 overlay 实际 content frame（排除状态栏/导航栏）计算，不用全屏 `displayMetrics`，否则下半屏时面板与气泡会多出系统栏高度。鲸鱼娘四态取自 `assets/ui-kit/whale-flat-v1`（idle/wave/thinking/sleepy），只表达状态，成败仍以工具结果与文字为准。插件连接流程在 App 不在前台时也占一张事件卡：优先级 提问 > 插件连接 > 完成，气泡表情为招手，不占待处理角标数字；卡片显示插件名与当前步骤，点卡片回到 App 继续，连接结束即消失，关闭键只在本轮连接内生效。
30. **虚拟屏幕是特权插件**：用 `app_process` helper 在 shell uid 2000 下创建 trusted VirtualDisplay，宽高与 dpi 由 helper 取真实屏幕指标：宽=短边、高=长边、dpi=真实 densityDpi，**始终竖屏**，App 不再下发尺寸；实测 Android 16 上 VirtualDisplay 不继承主屏 rotation（主屏 ROTATION_90 时 VD 仍 rotation=0、1220×2712）。`am start --display` 启动 App，反射 `InputManager` 注入输入、ImageReader 取帧；helper 必须 uid 2000（uid 0 会被系统「包名与 uid 不匹配」校验拒绝），root 路径为 `su -c "su 2000 -c ..."`。IPC 改为 App 建 loopback TCP `ServerSocket`、helper 反向 connect `127.0.0.1:port`（抽象 LocalSocket 在 shell 域被 SELinux 拒绝，实测超时）；hello 携带 uid + 一次性 nonce 双校验。帧流 360 宽 JPEG ≈12fps，截图在无新帧时回退最近一帧缓存。插件要求选了特权档且无线调试/Root 至少一个实际可用；启动顺序见 27；按屏无障碍读取见 33。已知限制：helper 的 `text` 只支持 ASCII；loopback TCP 仅 token/nonce 防护，理论上本机其他进程可抢连导致一次启动失败（重试即可）。预览帧改为 5fps，帧编码不再每帧复制整幅 RGBA（复用 full-res/preview 两块 Bitmap 做 Canvas 裁剪缩放，单帧只分配 JPEG 字节），截图回退缓存按 ≥1s 节流；TEXT/SCREENSHOT 命令响应由命令线程直写、BINARY 预览帧走容量 2 的队列 + 单写线程，队列满丢帧，避免帧背压把命令响应拖过 App 的 10s 超时；tap/swipe 注入前校验坐标是否在虚拟屏范围内并给出明确错误；HELLO 帧携带 `pid`，ShellDaemon 日志 append 并记录 helper pid，便于断连归因。
31. **ui-kit 鲸鱼娘素材的用途**：`assets/ui-kit/whale-flat-v1` 的 `mascot_idle/wave/thinking/sleepy` 导出为 192px WebP 放 `drawable-nodpi`，只用于悬浮窗气泡的状态表情（运行 thinking、待处理 wave、常态 idle、长时间无事件 sleepy）；不做按钮底色或可拉伸九宫格，UI 组件仍用 Compose 绘制。
32. **内嵌无线调试配对与守护进程**：首次配对由 App 发通知（RemoteInput 6 位码）并打开开发者选项；若系统通知不支持内联输入（如 MIUI 只能整条提交空值），点「配对无线调试」时 App 同时弹出内联输入弹窗，保持系统配对页可见（必要时分屏）后把 6 位码填进通知或 App 弹窗，receiver 用 libadb 完成 TLS 配对并自动点火 `ShellDaemon`。通知权限不再阻塞配对（通知发不出去时仍可用 App 内弹窗）。权限页在已配对/守护运行时仍提供「重新配对无线调试」入口，信任被系统删除后可直接重配，无需重置 App 或杀进程。无线调试连接发现做 8s × 3 次重试，成功后把端口缓存到私有 prefs，下次优先直连 `127.0.0.1:<缓存端口>` 绕开 mDNS（实测 MIUI 的 NsdService 会把 IPv6 链路本地地址解析结果丢掉，导致「配对成功但连不上」）。守护进程用 APK 自身的 `app_process` + `CLASSPATH` 启动，绑定 `127.0.0.1:18242`，用 `X-Token` 鉴权；只保留 `/health`、`/exec`、`/start-helper`、`/kill-helper`，旧的主屏 `/tap`、`/swipe`、`/settings` 已删除，屏幕注入统一走 `input`/helper。daemon 生命周期挂在 adbd 的 cgroup 上：关闭无线调试或重启后 adbd 退出，daemon 随之被系统清理；App 重新打开无线调试后点「连接并启动守护进程」即可重新点火，无需重新配对。App 升级保留 `files/adb` 下的 key/cert 与 prefs 里的 paired/token；force-stop App 不会杀 daemon。token 通过命令行传给 daemon，`/proc` 对 shell/root 可见；HTTP 明文只对 loopback 白名单放行（network_security_config），不暴露到局域网。
33. **双屏 GUI，优先虚拟屏**：按用户最新选择恢复主屏，screen_* 可选 target=virtual|main，省略时默认 virtual；提示模型优先虚拟屏，主屏须显式选择，失败不自动换屏。无障碍按 display 读取节点、节点定位与 Unicode 输入；虚拟屏 helper 提供坐标手势、截图、ASCII 输入与启动应用，交互要求虚拟屏在线，列表不要求在线。主屏无需虚拟屏在线，手势通过无障碍或已授权的 ADB/Root，系统输入显式指定 display 0；无障碍全局按键在另一屏拥有焦点时拒绝，主屏截图使用 Android 11+ 无障碍接口，锁屏或受保护窗口报错。启动应用前检查所在屏幕，拒绝移动另一屏上的任务；无特权时只在虚拟屏确认停止后允许主屏启动，并验证实际落点。ref 绑定所选屏幕、窗口和最新快照，观察、窗口变化或屏幕重建后重新获取；过滤按 AND 组合，扫描与返回预算分别计数，截断时不声称穷尽。取消传播、不自动重跑；恢复不迁移文件或历史会话，不恢复旧 gui_* 工具、含糊的活动窗口回落或 daemon 主屏端点。

34. **无障碍自动配置**：ADB 守护就绪后由 `PrivilegeControllerImpl` 触发 `AccessibilityBootstrapRunner`，通过 daemon 用 `settings put secure enabled_accessibility_services` 合并写入本应用组件（保留其他已启用服务）并置 `accessibility_enabled=1`；触发时机为 daemon `false→true` 上升沿与 App 启动/选择特权档/手动连接，幂等、15s 节流、失败退避重试 2 次后静默等下次触发，不做轮询对抗用户手动关闭。HyperOS/MIUI 的 force-stop 会经 AMS `onPackagesForceStoppedLocked` 把本包从启用列表摘掉，所以每次冷启动/重连都要重新确保一次；首次安装且 ADB 尚未就绪时仍可能需要用户手动开启一次无障碍。

35. **虚拟屏连接可靠性**：App→helper 每秒 tick、每 5s 发 PING（负数 id，不占业务命令通道）、15s 无 pong 判定 transport lost；命令响应按 id 关联（pong 隔离、超时 id 记 abandoned、迟到响应丢弃），截图用 epoch 关联并在超时后丢弃迟到帧；`start()` 在 Online 时先做 2s 健康 ping，失败则清理重建（修复半开连接无法恢复）；transport lost 后按 1s/3s/10s 最多自动重连 3 次，`stop()`/手动 start 取消重连，BACKEND_UNAVAILABLE 首次即放弃；重连成功写 `lastTransportNotice`、失败写结构化 `lastFailure(category=TRANSPORT/BACKEND/START, recoverable, reason)`，screen 工具层据此给模型可操作提示；所有失败路径打结构化 transport 日志（event/reason/backend/helperPid/displayId），readLoop EOF 不再静默。

36. **工具说明与暴露粒度**：说明保留正确操作所需的环境、路径、权限、输出截断、取消与恢复契约，不设字符上限或术语黑名单。规则按实际工具和会话能力生成，不无条件要求 present，不规定失败两次必须停；已有授权内直接执行，超出授权的破坏性或不可逆动作再询问。get_goal/create_goal/update_goal、job_start/output/list/kill、schedule_create/list/update/delete 分别暴露，参数保持 camelCase，拒绝不适用参数。screen 手势保持原子，screen_list_apps 与 screen_launch 分开；virtual_screen(action=start|stop|status) 保留。历史工具记录不改写；新调用使用新接口。SDK 固定 0.2.4。**跨调用规则只有一个 owner**：每条规则挂在所属工具的 `promptGuidelines` 上（文件工具、bash、系统 shell、屏幕、日历、联网搜索等），运行时按当前实际工具集汇总去重成 `<rules>`，不再在汇总函数里手写工具名 if 链；工具未注册时它的规则随之消失，不会留下过期规则。工具 description 只写单次调用的语义与结果形态，不重复跨调用规则与其它工具的说明。

37. **绝对路径**：文件工具、交付与工坊装载必须显式传真实绝对路径，拒绝相对路径、~ 和省略路径；工作区只注入提示词提醒，不据此补全或限制访问。App files/cache 在 Linux 中同路径映射，贯通工作文件、截图、技能、工坊、下载和日志，不再支持 /workspace、/gui、/skills 等别名。文件定位结果使用绝对路径，交付必须检查存在、可读且为普通文件；不改写正文、HTML 资源引用、glob 或 shell 命令。无需迁移既有文件或会话。

38. **第三方依赖按需判断**：不再默认禁止第三方库，也不预设「优先用库」或「优先自己写」的倾向；按具体需求评估——现成成熟库能明显省事就用，自己实现更简单就不引入。新增依赖需在本文件记录用途、许可与体积影响；模块依赖图、`settings.gradle.kts`、签名配置、`.gitignore` 仍不经说明不改。本条取代规则页原先的「不加第三方依赖」，既有的 #28 依赖记录保持不变；本轮文件预览（Markdown/HTML/源码/视频）未新增依赖。

39. **插件 setup 的自定义界面**：`plugin_setup` 的工具契约与外壳（安装确认、取消、进度、系统通知、失败回退）仍由框架统一提供；插件的自定义界面只在 setup sheet 的内容区获得一个 Composable 槽，用来替换默认的阶段/URL/二维码视图，槽内滚动与状态由插件自管，框架不解析、不渲染模型生成的结构化 UI。需要独立返回栈或全屏的流程仍由插件自己开 Activity，这些页面同样计入 App 前台，不会在页内重复提醒；连接流程必须在前台启动，App 不在前台时只通过悬浮窗事件卡提醒用户回到 App 继续。
