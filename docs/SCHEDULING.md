# 定时任务设计

状态：提醒投递、任务页编辑、手动执行均已实现。

## 模型

一个提醒属于**创建它的那个对话**。到点由宿主把一条提醒消息投进该对话，并在那里开始一次运行：

- 不新建会话，不另开工作区；模型带着原对话的历史、AGENTS.md、skills 和工作区 cwd 继续。
- 提醒是一条 user 角色消息，首行为 `[定时提醒] 名称`；聊天里显示为「定时提醒 · 名称」标签，气泡正文只显示提醒内容。
- 提醒运行与其他运行没有区别：前台通知、完成通知、停止、重载都按普通会话处理。

## 数据

`files/schedules/schedules.json`，`schemaVersion` 2，临时文件 + 原子替换；损坏时保留原文件并报错。

```text
Schedule
  id: String
  name: String
  prompt: String
  trigger: Trigger
  enabled: Boolean
  sessionId: String      绑定的对话
  sessionFile: String    对话文件，冷启动时据此重新打开
  cwd: String            对话的工作区
  nextRunAt: Long?       下次投递时间（epoch ms）
  lastDeliveredAt: Long?
  lastError: ScheduleError?
  createdAt: Long
  updatedAt: Long

Trigger
  Once(date: LocalDate, time: LocalTime)
  Daily(time: LocalTime)
  Weekly(days: Set<DayOfWeek>, time: LocalTime)
```

- 使用设备本地时区；不保存 API Key，提醒内容按本地明文保存。
- `enabled = false` 时 `nextRunAt = null`；重新启用时按规则重算。
- 一次性提醒投递后自动停用，`nextRunAt = null`，记录保留在任务页的「已停用」分组，可删除。
- `lastError` 只存错误码：`SESSION_MISSING`、`OPEN_FAILED`、`DELIVERY_FAILED`，界面按语言环境显示对应文案。

## 投递

`ScheduleService` 在前台服务进程内运行，负责计时、批量、投递与状态发布。

- 启动时先读盘并补投一次：进程不在期间错过的任务，在下次服务启动时各补投一次（只补最近一次，不重放历史）。
- 计时没有固定 tick：按最近一个 `nextRunAt` 计算等待时间（上限 15 分钟兜底），存储变更或会话事件会立即唤醒重算。
- 到期任务按 `sessionId` 分组；同一对话的多条提醒合并成一条批量提醒，只触发一次运行。
- 投递前先打开会话文件；会话缺失记 `SESSION_MISSING`，打开失败记 `OPEN_FAILED`，发送失败记 `DELIVERY_FAILED`。失败后按规则推进下一次或停用，不原地空转。
- 投递串行执行（Mutex）；手动执行与定时投递共用同一路径。
- 设备时间或时区变化时重算所有启用任务的下一次时间。

提醒文案：

```text
[定时提醒] 名称
这是你设置的定时提醒，现在到时间了。

提醒内容
```

批量时首行为 `[定时提醒] N 个提醒`，正文按序号列出每条的名称与内容。

## 生命周期

- 删除对话：其提醒一并删除。
- 归档对话：其提醒停用（解除归档不会自动恢复）。
- 前台服务被杀：不唤醒；下次打开 App 补投一次。
- 删除或改写绑定对话的文件：投递失败并记录错误码。

## 工具

`schedule_create`、`schedule_list`、`schedule_update`、`schedule_delete` 绑定到调用它们的会话：

- 只能看到、修改、删除当前会话的提醒；创建即绑定当前会话，无需指定工作区。
- `schedule_create` 参数：`prompt`、`frequency`（once / daily / weekdays / weekends / weekly）、`name`、`date`、`time`、`weekdays`。
- `schedule_list/update/delete` 只作用于当前会话；`update` 可改名称、内容、触发与启用状态，不能改绑对话。
- 工具与任务页写同一个存储；`ScheduleService` 订阅存储变更即时重算，无需重启。

## 任务页

- 列表按「已启用 / 已停用」分组，行内显示名称、下次投递时间与规则，右侧启用开关。
- 编辑器（新建 / 编辑共用）：名称、提醒内容、重复规则（一次 / 每天 / 工作日 / 周末 / 每周）、时间、日期（仅一次性）、星期（仅每周）、投递到、启用。
- 每次保存重新校验：名称与内容非空、一次性时间必须在未来、每周至少一天、必须选择对话。
- 编辑已有任务时可立即执行（立即投递，不改下次投递时间）或删除（确认后删除）。
- 所有文案中英双语；错误与空态同样走字符串资源。

## 迁移

- 从 v1（工作区绑定、执行会话、隐藏工作区）升级：旧任务全部丢弃并写回空 v2，旧隐藏工作区目录不再被读取或展示。

## 失败

| 情况 | 处理 |
|---|---|
| 服务被杀 | 本次跳过，下次打开补投一次 |
| 对话文件缺失 | `SESSION_MISSING`，任务保留；一次性停用 |
| 打开对话失败 | `OPEN_FAILED`，任务保留；一次性停用 |
| 发送失败 | `DELIVERY_FAILED`，任务保留；一次性停用 |
| 同一对话多条同时到点 | 合并为一条批量提醒 |
| 手动执行与定时同时发生 | 串行，不并发 |
| JSON 损坏 | 保留原文件并报错，不覆盖 |

## 限制

- 投递依赖前台服务存活；不使用 AlarmManager、WorkManager、精确闹钟权限，进程不在时不唤醒。
- 重复规则只有一次 / 每天 / 工作日 / 周末 / 每周，不提供 cron 与自定义间隔。
- 使用设备时区，不提供按任务选择时区。
- 手动执行不占用当前到点的那次投递；若恰好在到点瞬间手动执行，可能再投递一次。
- 旧隐藏工作区目录 `files/schedules/workspace` 不再引用，也不主动删除。

## 验收

- 新建每天提醒：服务存活时按计划投递到绑定对话，内容带标签，助手在原对话里接着回复。
- 一次性提醒投递后停用，任务页显示上次投递时间。
- 到点前杀进程，重开 App 后补投一次，不重复。
- 同一对话两条同时到点只触发一次运行。
- 编辑规则后无需重启即按新时间投递；关闭开关后不再投递。
- 立即执行立刻出现在对话里，下次投递时间不变。
- 删除对话后任务消失；归档对话后任务停用。
- 时间/时区变化后按新本地时间重算。
- 任务页与聊天内提醒状态实时更新，无轮询。
