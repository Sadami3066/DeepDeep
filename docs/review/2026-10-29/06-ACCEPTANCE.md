# 整合后的场景验收矩阵

本表是建议验收合同。标记“复现缺陷”是本轮已经观察到当前错误行为；“静态确认/风险”需要实现时增加组合测试；“未测”不能在交付说明中写成通过。

| 场景 | 必须验证的结果 | 本轮状态 |
|---|---|---|
| A 发消息 + B 同时发消息 | 两个会话独立，model/cwd/tool/result/runId 不串 | 架构路径已审阅，未做真实 Host 并发测试 |
| 同会话用户发送与提醒同时到达 | 只启动一个 run，另一个有序排队；无 busy 假清零 | 静态高风险 R01 |
| 同会话 job 完成、目标续跑、用户输入同到 | 明确队列优先级/来源，用户输入不被覆盖 | 未测 |
| 运行中切换会话再返回 | UI 缓存与权威快照一致；旧 run delta 不写进新轮 | 现有 ViewModel 用例覆盖部分路径 |
| 模型失败与 SDK 自动重试 | 总重试预算清楚，最终只有一个 outcome | 层间策略已审阅，组合未测 |
| App 自动重试倒计时中停止 | 不再启动重试，UI 回到可输入 | **复现缺陷 B03** |
| bash 正在执行时停止 | 进入 stopping，进程退出/settled 后终结；无孤儿进程 | shell 单测有取消；Host 完整链未测 |
| 提问等待中停止 | pending 被取消，deferred 结束，重开不再显示互动卡 | 纯 QuestionCenter 有测试，恢复链未测 |
| 目标续跑 400ms 内暂停/清除/编辑 | 旧 revision 不执行；轮次只在真正启动时增加 | 静态问题 R03 |
| 插件变更与新消息同时发生 | 运行会话不被关闭，能力在安全点更新 | 静态高风险 R02 |
| 会话切模型/思考 | 仅目标会话变化；重启由 JSONL 恢复 | 当前实现与部分现有测试确认 |
| JSONL 完整尾行缺 LF 后继续写 | 原记录与新记录均可恢复 | 静态风险，同类尾部契约 |
| JSONL 半条尾行后继续写 | 坏尾隔离，新记录可见，重复重开不丢 | **复现缺陷 B02** |
| 持久写入前/后 kill 进程 | 不报告未提交成功；恢复状态可解释 | 未做进程故障注入 |
| 连续保存 Key / OAuth 刷新后登出 | 最新意图持久化，旧刷新不能复活 | **复现乱序 B06** |
| 工坊文件工具访问 ../ 或绝对路径 | 在明确作用域外拒绝，含 symlink | **复现边界缺陷 B01** |
| 工坊页面尝试读其他创意 KV | 当前创意绑定不可越过；Agent 数据工具也按 scope | 网页绑定路径已审阅，Agent scope 不足 |
| 工坊默认工具与选择空数组 | null/空数组含义明确；默认不能隐式继承全部能力 | 已有目录选择测试；边界不足 |
| 同网页并发调用 100 个 agent.run | 有并发/费用/取消/队列上限；可预测错误 | 静态缺少统一预算，未压测 |
| 关闭/重载工坊页面 | 所有请求按合同取消或后台持久化，旧响应不注入新页 | 生命周期已审阅，组合未测 |
| 极长无换行输出 | 上游、队列、输出存储与模型内容均有上限 | **复现缺陷 B08** |
| 大文件 read(offset,limit) | 不读入整文件；结果与游标正确 | 静态问题 R05 |
| 两会话修改同 cwd 同文件 | 可检测读写冲突，避免静默覆盖 | 每 session 队列不足，未测 |
| rootfs 文件数扩大 | 执行前检查 O(1)，磁盘大小统计移出命令路径 | **性能观察 B09** |
| 已装插件升级在下载/校验/切换各阶段失败 | 旧版继续可用，账号/技能/记录保持一致 | **复现缺陷 B04** |
| 上海/纽约/UTC 全天事件 | 用户日期原样进入 Provider，跨日和 DST 正确 | **上海复现 B05**；Provider 跨时区未测 |
| 用户改系统时间越过提醒触发点 | 未投递提醒保留补投机会，不静默禁用 | **复现缺陷 B07** |
| 用户改系统时区 | 使用新的 ZoneId 计算未来，历史执行不被改写 | Clock 固定 zone 静态问题 |
| 提醒排队后、启动前进程死亡 | 重启只补投一次，不丢、不重复 | outbox 缺口，未测 |
| 会话删除/归档与提醒触发并发 | 生命周期与投递在统一事务/队列里决定 | 事件驱动清理已审阅，竞态未测 |
| 很老会话收到新消息 | lastActivityAt 更新，抽屉按最近活动排列 | 静态问题 R06 |
| 1000 长日志会话列表与搜索 | 取消有效；列表不反复解析正文；索引可重建 | 有小日志合成性能观察 |
| 长 Markdown 流式更新 | 不阻塞主线程、旧解析不覆盖新文本 | 有本机解析/归约观察，无真机帧结论 |
| 前后台/服务重建/系统杀进程 | 任务有恢复/未知状态；通知可解释 | 静态审阅；按要求不进行真机实测 |
| 打开很多会话/工坊/已结束 job | 有明确保留/关闭预算 | 仅静态分析；未做内存测试 |

最低门槛：所有 P1 对应场景转为断言正确行为的回归测试；任何模型/工具外部副作用的重试必须先定义幂等或 unknown outcome。正式验收要分别记录“纯规则通过”“SDK 集成通过”“Android 系统/真机通过”“真实服务任务通过”，不能把前三者之一泛称为端到端可用。
