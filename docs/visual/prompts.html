提示词是怎么拼起来的

一次会话的系统提示词像一叠卡片：SDK 放最前面 5 张固定卡，App 在后面插 9 张动态卡。每轮只换“有变化”的那几张。

1谁在拼：两层，各管各的

SDK 负责「读文件」的部分 会话创建时读一次，之后不变：
  • SYSTEM.md（身份与总规则）
  • 项目里的 AGENTS.md / CLAUDE.md
  • skills 的清单（只有名字+描述）
  • 当前工作目录
App 负责「运行时」的部分 每轮都能刷新：
  • 工具规则（rules 段）
  • 时间/模型/称呼/交互风格
  • 插件提示段、插件上下文
  • 记忆快照、路径、MCP 状态
你可以把系统提示词想成 一次请求里的“系统消息”，它和另外两样东西一起送给模型：
① 系统提示词（这一叠卡片）　② 工具清单（单独一栏，JSON 描述）　③ 聊天记录
发请求时，模型看到 系统提示词
+ 工具清单
+ 对话历史
+ 你这句话
注意 工具的描述不在系统提示词里，它是单独一栏；系统提示词里只有 rules 段里的一句话约束。

214 张卡片的顺序

1
preamble（裸文本） 固定
SYSTEM.md：身份 + “简洁直接” + 不编造结果
2
<addendum> 固定
APPEND_SYSTEM.md（可选）
3
<project_context> 固定
AGENTS.md / CLAUDE.md，逐级向上收集
4
<skills> 固定
技能清单：名字 + 描述 + 位置（正文要用时再读）
5
<cwd> 固定
当前工作目录
6
<rules> 会变
4 条全局规则 + 所有工具的“注意事项”（工具增删时会变）
7
<environment> 会变
今天的日期、当前模型、称呼、交互风格
8
<instruction> 条件
你写下的长期偏好（设置了才有）
9
<shared_storage> 条件
共享存储开关说明（开了才有）
10
<official_plugins> 会变
所有已启用插件的提示段，按优先级拼成一段（没有插件名标签）
11
<memory> 会变
记忆快照：用户/速查/项目/今天/昨天（最多 16000 字）
12
<paths> 固定
技能目录、App 私有数据目录
13
<plugin_context> 每轮
插件每轮临时提供的上下文（最多 8K/插件，总 32K）
14
<mcp_servers> 条件
MCP 服务器状态（配了才有）

“会变”不等于每轮都变：只有内容真的变了才会发新的一份；一直不变就一直沿用旧的。

3三个容易误解的点

① SDK 自带的 tools / rules / docs 三段不会出现。因为 DeepDeep 总会写一份 SYSTEM.md 当“自定义开头”，SDK 看到后就不再生成这三段。所以「规则」全部来自 App 自己的 rules 段（4 条全局 + 工具注意事项）。
② 工具的「描述」不进系统提示词。工具名、说明、参数格式是作为工具清单单独发给模型的；会对提示词产生影响的，只有工具里写的“注意事项”（promptGuidelines）被收进 rules 段。
③ 系统提示词只在“有变化”时追加补丁。SDK 每轮重建一次这叠卡片，和上一轮比对：哪段不一样就发哪段。所以改一句环境文案，下一轮就会多一条系统消息；而记忆快照、插件段这类不变的内容不会重复发——这也是它们“冻结”能省 token 的原因。
