记忆系统是怎么工作的

一句话：每次会话开始时，模型带着一本「记忆便签」进来；聊天中它能随时翻查、随手记录；会话结束后，它自己把这段经历写进当天日记。

1它其实只有 4 个 Markdown 文件

全部存在手机上 files/agent/memory/，就是普通文本，随时能看、能改、能备份。

👤
profile.md — 用户与协作 你是谁、偏好和雷区、以及“我该怎么跟你配合”
🎯
context.md — 目标与项目 我们在做什么、做到哪一步、卡在哪、答应过什么
🧠
playbook.md — 策略与技能 什么方法对你有用、踩过什么坑（顶部「速查」会被注入）
📅
daily/2026-11-07.md — 共同经历 当天发生的事 + 每个会话结束自动写的纪要

2一次会话的 4 个时刻

会话开始：把记忆拼成「快照」塞进系统提示词 只做一次 按固定的顺序和预算，把 4 个文件里该看的部分拼成一段文字，放在模型最前面的系统提示词里。之后整场会话不再更新——保证“记忆”稳定，也省 token。 
## Memory
Snapshot session_start at 2026-11-07 21:05:51. Use memory_search for the latest state.

## 长期记忆（快照 2026-11-07 21:05:51，会话内不会自动刷新）
需要更新或更细的记忆时先调用 memory_search；写入或修改长期记忆用 memory_write……
### 用户与协作      （最多 2500 字）
### 方法速查        （最多 800 字，playbook 顶部的速查）
### 目标与项目      （最多 2500 字）
### 今天（2026-11-07）（最多 3000 字）
### 昨天（2026-11-06）（最多 2000 字）
整段总共不超过 16000 字
聊天中：模型用 4 个工具读写记忆 随时 想记住就写，想回忆就搜。写文件不会刷新已经注入的快照，所以不会打断当前对话的缓存。
memory_write
写一条到 profile / context / playbook / daily；daily 只能追加
memory_search
全库关键词搜索（中英文都行，本地毫秒级），返回带文件和片段
memory_read
看某个文件的原文，改动前先读，避免覆盖掉别的
memory_status
查“现在记忆里有什么”：字数、项目数、日志天数、快照状态
上下文快满、准备压缩前：留一份「交接」 自动 把 context.md 里的「近期焦点」+ 今天日志最后 15 行，追加进当天 daily 的 ## Session Handoff。这样压缩掉旧消息后，下一个自己还能接上。
会话结束：用便宜模型写一段「纪要」 自动 两种情况才写：闲置 5 分钟被回收、或你主动关闭。纪要是一条没有固定格式的列表（最多 6 条，值得记才写，不值得就跳过），写进当天 daily。切模型、重载、删除会话都不会触发。 

## 会话纪要（自动沉淀）
- 用户在开发 DeepDeep 的记忆系统，本轮把纪要改成增量式
- 决定：纪要只在闲置回收/会话关闭时触发，其余关闭原因丢弃
- 未完成：提示词描述文案还没开始改

3数据怎么流动

你聊天 —— 模型判断哪些值得记，用 memory_write 写文件
↓
平时 —— 写进 4 个 md；daily 只追加，curated 文件可改可重写
↓
每次新会话开始时 —— 把最新内容拼成快照 → 注入系统提示词 → 模型“记得”
↓
会话结束时 —— 自动纪要写回 daily → 下次快照里就带上这段经历
所以记忆不是“一直活着”的，而是：写下来 → 下次开会话时读出来。已经开着的旧会话不会热更新，想看最新内容就让模型用 memory_search。

4想自己改，从哪下手

  • 注入的那段文字（标题、顺序、预算）：runtime/.../memory/MemoryMarkdown.kt 的 renderMemorySection
  • 纪要的提示词（写几条、什么语气、什么时候 SKIP）：runtime/.../memory/MemoryRecap.kt 的 buildPrompt
  • 工具描述（模型什么时候该用哪个）：runtime/.../memory/MemoryTools.kt，以及它汇进系统提示词 rules 段的 guideline
  • 文件本身：手机 files/agent/memory/，或记忆页（抽屉 →「记忆」）看状态、手动沉淀
